## Source findings and scope boundaries

- [Official useAnimate](https://motion.dev/docs/react-use-animate) distinguishes mini and hybrid imports but does not promise mini MotionConfig inheritance. [13.4.4 mini hook source](https://unpkg.com/framer-motion@13.4.4/dist/es/animation/hooks/use-animate-style.mjs) creates a scoped WAAPI animator and cleanup only. It reads neither MotionConfig nor reduced-motion policy. [13.4.4 hybrid hook source](https://unpkg.com/framer-motion@13.4.4/dist/es/animation/hooks/use-animate.mjs) reads reduced motion and skipAnimations. Astra additionally offers documented transition-default inheritance in its hybrid helper; mini deliberately does not inherit it. Existing mini documentation is accurate.
- [13.4.4 arc source](https://unpkg.com/motion-dom@13.4.4/dist/es/animation/utils/arc.mjs) provides the geometry used in these tests. [animateTarget](https://unpkg.com/motion-dom@13.4.4/dist/es/animation/interfaces/visual-element-target.mjs) invokes the path hook; [animateElement](https://unpkg.com/motion-dom@13.4.4/dist/es/animation/animate/element.mjs) and [animateValues](https://unpkg.com/motion-dom@13.4.4/dist/es/animation/animate/effects.mjs) do not. The [official arc reference](https://motion.dev/docs/arc), reread 2026-09-28, promises direct components, animate and useAnimate. The hybrid correction closes a documentation/engine discrepancy; it does not claim the upstream implementation already works. The same article calls strength=1 a peak height equal to travel distance, but the symmetric quadratic source places its control point there and reaches half that displacement at t=0.5. Astra retains upstream geometry and records this disagreement.
- DOM subject calls and path-bearing sequence segments are implemented. `sequence-path.ts` resolves segment placement using the qualified engine timing rules and delegates ordinary properties/callbacks and the resulting per-element clocks to the public upstream sequence function. Arc coordinates use exact engine samples, with first/last x/y array values; they are not approximated with a sampled keyframe mesh. Each element owns its x/y driver independently, while returned group controls coordinate all tracks. Ordinary positional overlaps are sampled from scratch timelines compiled by the public upstream sequence function, preserving its original endpoint and keyframe-erasure behavior. The decisive Chromium case covers labels, relative at, delays between segments, array endpoints, paint/callback composition, forward/backward seeks, replacement and teardown. Arbitrary custom MotionPath implementations that depend on VisualElement internals beyond the public arc value-owner usage are not established by this fixture.
- Upstream zero-duration animations schedule immediate frame work without returning a driver. Hidden control commands are protected by queuing before engine invocation. The source's general zero-duration start-then-stop-in-the-same-frame semantics are not broadened into a new cancellation promise by this increment.
- Factory-created native tags expose a typed ref binding. Native two-way form bindings remain on the compiled `motion.input`/`motion.select`/`motion.textarea` APIs. Custom factory components retain their declared Svelte bindings. This distinction must remain visible in factory reference prose.
- The previously approved Activity adaptation remains unchanged: retain component/DOM state, coordinate exits, suspend Astra-owned work while hidden, and use `useActivityEffect` for application work. Ordinary Svelte effects remain active.

## Sequence follow-up and independent review correction

The isolated sequence increment adds `src/lib/motion/sequence-path.ts` and changes only `animation.ts`, `use-animate.svelte.ts`, `ParityCompositionPath.svelte` and `parity-composition.svelte.spec.ts` from the stable runtime manifest. It uses public engine exports; no deep React imports, dependency copies, prototype changes or new dependency identity are introduced.

The fresh adversarial reviewer identified a real ownership error in the first draft: a single clock shared by different elements meant replacing one element's x/y stopped its peers. The final implementation has one clock per element inside the same upstream sequence group. The existing decisive case now animates both an ordinary HTML node and a motion node, replaces the first, and verifies the second driver stays running and reaches its endpoint. It also verifies shared x/y identity within each element and distinct drivers between elements.

The reviewer then identified a separate overlap error: retaining the newest ordinary positional sampler indefinitely lost older endpoints that Motion's sequence compiler preserves. The final adapter delegates the complete positional baseline to the public upstream sequence compiler and samples its stopped numeric drivers exactly. Arc geometry overrides only its active interval; after replacement, the compiled timeline determines the remaining coordinates. The same decisive case verifies a 0-to-100 segment ending at t=2, a later override to 50 ending at t=1.2, the interpolation back to x=75 at t=1.6, and the preserved x=100 endpoint at t=2. No second hand-written keyframe-erasure algorithm is introduced.

The final source review found that an overlapping arc must start from the preceding active curve, rather than the ordinary compiled baseline. Arc construction now samples that preceding curve at the interruption boundary for implicit coordinates; explicit first keyframes retain their override. The same case verifies continuity at (50,50) when a strength=1 arc from (0,0) to (100,0) is replaced halfway through its two-second duration. This keeps curved continuity alongside the source-compiled ordinary endpoint behavior. The final Chromium run passes with all three reviewer corrections.
