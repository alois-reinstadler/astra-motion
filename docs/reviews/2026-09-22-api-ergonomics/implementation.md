## Authoring model now implemented

Use `import { motion } from 'astra-motion'` and a compiled tag component for ordinary new markup. `motion.button` renders a real button and accepts button attributes, events, children, motion options and a typed `bind:ref`. `motion.input` implements native value, checkbox and file bindings through Svelte's binding directives. Textarea, single/object/multiple selects and details have their corresponding supported bindings. There are 101 HTML content tags; generated output is checked by `check:elements` during packaging.

This is a static namespace of compiled components, not a runtime proxy or universal HOC. The [generator](../../../scripts/generate-motion-elements.mjs) and [types](../../../src/lib/motion/elements/types.ts) define the surface. Input binding categories and select modes have separate internal components so retained exits do not reuse a binding on another element. Ref cleanup only clears the node it installed. A Vite probe retained only the button wrapper when importing `motion.button`; namespace and direct-button output were 240,153 and 240,180 bytes in that unminified probe. This establishes wrapper elimination for static access, not a universal bundle-size promise.

Keep generic `Motion as="button"` compatible. Its dynamic element still cannot supply native value bindings. Use `createMotion` on existing native or headless markup, for native directives and parent-scoped selectors, and for `bind:group`. Media, contenteditable and dimension bindings, SVG tags, custom elements and arbitrary component factories are not added. This remains a motion library.

## Correctness changes

- **Reactive options:** nested plain option objects and arrays are read in the owning effect before deferred engine work. MotionValues and non-plain objects keep identity. Selected variant functions track their consumed custom/state reads. The regression mutates and replaces nested object, getter, component, variant and custom targets without remounting their visuals.
- **SSR variants:** tag components and generic Motion share a component-context binding helper. Children inherit the parent's declared variant labels and `initial: false` during SSR. Native bindings retain explicit `parent.child()` semantics. Declared children must still mount inside the parent's DOM; this does not create cross-portal projection support.
- **Transform composition:** paint-only state bindings preserve existing CSS transforms. Acquiring transforms, layout or drag checks for conflict, including later reactive/imperative targets. Deferred ownership errors re-enter the binding's Svelte effect so a surrounding boundary can dispose and recover.
- **Retained route sources:** route attachments acknowledge a document checkpoint through their owning Svelte effect. Paused outgoing branches do not acknowledge it. Old shared nodes retained solely by an unrelated exiting sibling are excluded from the incoming snapshot, while persistent and resumed branches remain eligible. Existing duplicate-live-ID diagnostics remain.
- **Timeline policy and settlement:** attached scopes observe local reactive policy objects/getters as well as inherited/OS policy. Reduction completes the original ordinary playback instead of silently replacing it. `controls.settled` resolves `{ status: 'finished' }` or `{ status: 'cancelled', reason }`, with stopped/cancelled/replaced/detached reasons. A replay after completion gets a new promise. Legacy Motion cancellation promises retain their existing behavior.

The last change includes a narrow Motion 13.2 compatibility path for WAAPI infinite iterations and zero playback speed. It preserves repeat/direction settings and finishes the original controls. Newly consumed `NativeAnimation`, `isAnimationControls` and `isMotionValue` exports are recorded in the upstream gate. External `attachTimeline()` remains an explicit lower-level limit: Motion disables its native finish callback; cleanup, explicit complete or reduction detaches that timeline and settles cancelled. Prefer `createScroll` for Astra-owned scroll motion.

## Package boundary and migration

The tarball now contains one qualified DOM-only engine graph: motion-dom/framer-motion 13.2.0 and motion-utils 13.0.0. Development uses the same exact pins. Packaging preserves ESM module boundaries, copies licenses/provenance and rewrites import locations. It removes one unsupported Electron `webview` declaration; it does not introduce a fake ambient DOM type or modify upstream runtime algorithms.

Consumers no longer need Motion overrides or a separate Motion install. Create MotionValues through Astra's public values entry. Values from another independently installed Motion engine have no promised nominal type or engine identity compatibility. This is the material compatibility cost of owning the engine boundary; consumers using external values should switch their value/helper imports to Astra. Existing Astra call sites otherwise retain their signatures, and the tag namespace and settlement result are additive.

The package worker compared 13 isolated feature bundles before/after this packaging change: minified/gzip outputs were byte-identical. The archive grew from 49,920 to 261,728 bytes before adding the tag wrappers, because the previously transitive engine is now included. Do not confuse archive size with downstream tree-shaken bundle size. These figures qualify the packaging change alone, not the entire final feature addition.

## Effects, snapshots and the reported blur/shift

Browser setup in the site/showcase now uses `$effect` with `untrack`, returning cleanup to the effect. Reactive options and policy dependencies remain tracked. SSR initialization and server-relevant destruction are retained. This follows the user's preference without claiming a timing advantage over runes-mode `onMount`, which itself uses an untracked user effect in Svelte 5.57.

Neither spelling supplies a universal pre-mutation snapshot. [Svelte issue #16648](https://github.com/sveltejs/svelte/issues/16648) explains why child pre-effects can run after parent DOM mutations. [Issue #8547](https://github.com/sveltejs/svelte/issues/8547) is an additional reason not to infer current child order from setup order. Automatic layout keeps Astra's cached projection strategy; explicit `layout.update` snapshots before its synchronous mutation. No projection algorithm or rounding threshold was changed in this work.

**Missing or stale geometry can cause a wrong starting pose or interruption jump. It does not establish the cause of blurry text or a final 1–2 px shift.** Layout projection scales a box; text/images may be resampled during scaling, and fractional translations can affect rasterization. Motion's [layout documentation](https://motion.dev/docs/react-layout-animations) likewise distinguishes scale distortion and child correction. A large surface magnifies a small scale error: 0.001 across 1,000 px is 1 px. That is a possible mechanism, not the diagnosis of this report.

The user could not identify a reliable reproducer. Bounded checks used Chrome 152, device pixel ratio 1 and a 1440×1000 viewport:

- Development accordion, EditingDesk and ContactSheet measurements did not reproduce a 1–2 px final geometry jump. Late changes were roughly hundredths of a CSS pixel.
- The built EditingDesk Story-to-Cover transition changed a 520×580.71875 surface to 350×458.109375. In the [98 recorded frames](implementation-evidence/layout-frames.json), the last transformed pose differed from the settled pose by about **0.018 px in x, 0.013 px in y and 0.035 px in width**. Its last scale was 0.999899. Coordinates include page scroll; smooth scrolling was disabled for measurement.
- A settled screenshot was inspected and the console was clear. A screenshot of the endpoint does not prove the absence of transient rasterization blur.

No blur fix is claimed. Physical Safari/iOS, different DPR/zoom, GPU rasterization, image decode, font loading, scrollbar changes and the user's exact intermittent case remain unqualified. Keep these as diagnostic variables, not a speculative backlog of API features. A future reproducible failure should record old/target/final geometry and rendered transforms; compare automatic observation with an explicit transaction before changing snapshot machinery.

One existing layout test inspected geometry immediately after `tick()`. Its failure still contained the correct old cached box; the observer-triggered projection commit had not executed. Waiting for the next animation frame at the two first-paint assertions made the test meaningful and passed its unchanged continuity thresholds. Production scheduling was not changed to satisfy that test.
