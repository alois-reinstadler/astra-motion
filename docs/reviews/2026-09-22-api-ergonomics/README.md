# Review evidence and consumer

This directory accompanies [the API ergonomics review](../2026-09-22-api-ergonomics.md). `consumer/` is source for a small independently installed SvelteKit app. It imports Astra's packed public entries, never repository source. Its `$lib` alias is local to the consumer. It deliberately includes failures under `/mistakes`; it is an experiment, not a recommended production app.

`evidence.json` records the reviewed commit/archive, dependency graphs, strict diagnostics and browser observations. Names containing `qualified` use the documented four overrides; `production-core`, `route-production`, `ssr`, `dialog-final`, `hover` and the drag checks use the built app. Other original browser samples came from Vite development. The final fixture adds an image host and a second variant child, recorded in `final-layout-variants` after rebuilding. Timing/pose samples are observations, not portable thresholds.

To recreate the consumer, run `node docs/reviews/2026-09-22-api-ergonomics/prepare.mjs` from a repository with its dependencies already installed. The script packs the current checkout, copies these sources into a temporary directory, installs the tarball there, checks application types, and builds it. It renames the stored vite.config.ts.fixture inside the temporary app so the repository checker does not try to load that app before installation. It leaves repository production code and manifests unchanged. The script prints the location; archived evidence describes the original reviewed commit, not an arbitrary later checkout. The dependency versions in the fixture are deliberate comparison pins, not recommendations to upgrade.

The copied `pnpm-workspace.yaml` holds the qualified overrides. To investigate a fresh unoverridden install, use a separate copy without that file and with no preexisting lockfile/node_modules. Resolution is time-dependent; consult the recorded graphs for this review's exact result. The consumer lockfile is generated in the temporary app; the original lock hashes are in evidence. This fixture does not claim a bit-for-bit frozen transitive reproduction.

Inside the shared container, use `dev-preview start astra-review-consumer --cwd /the/printed/path -- env HOST='{host}' PORT='{port}' node build`. `--cwd` selects the temporary consumer; `--` separates the manager command from the server command; placeholders use the manager's allocated address and port. The server must stay in the foreground for the manager. Use the manager's printed loopback URL with the shared Chrome MCP, inspect console/network, and close your own tabs afterward. Do not launch another browser.

The normal consumer page contains all ten scenario ingredients; `/detail` is a real Kit route. `/route-probe` is the isolated shared-handoff control; add `?exit=1` to retain a plain shared sibling through an unrelated exit and reproduce the missed pairing, then `?exit=1&marked=1` to verify the zero-duration transition workaround. This workaround demonstrates the failure mechanism, not a proposed final API. `/mistakes` intentionally tests a reused binding and an opacity-only binding on authored CSS transform. The latter escapes its boundary on the reviewed version. Style-spread probes intentionally use both precedence orders. `Timeline.svelte` intentionally leaves completion state awaiting a stopped run, exposing the lifecycle problem. These are findings, not mistakes to copy into application code.

Strict declaration check: from the temporary consumer run `pnpm exec tsc --noEmit --skipLibCheck false --project tsconfig.json`. `--noEmit` prevents generated files, `--skipLibCheck false` checks dependency declarations, and `--project` selects the consumer configuration. It is expected to fail with the recorded upstream declaration on the reviewed graph; an ordinary app check does not supersede it.

The React companion is a documentation/source-verified comparison, not a running second app. Its version and execution limitations are explicit.
