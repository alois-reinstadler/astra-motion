# Release-candidate adoption documentation

Scope: documentation only, in the existing `agent/astra-rc-presence` worktree.
The preceding presence/reorder implementation was already integrated separately.
No runtime, dependency, preview registry or generated snippet-preview files changed
in this documentation pass.

## Decisions reflected

- Three authoring paths: typed `motion.*` for new elements, `motion.bind` for native
  markup/scoped CSS/directives, and `motion.create` for reusable custom roots.
- Native recipes include setup, reactive options, the SSR/attachment props spread,
  explicit native outro, configuration timing and `.child` ancestry. The spread
  already attaches the owner; recipes do not attach it twice.
- Historical `createMotion` remains explicitly supported with its historical defaults.
  The baseline already documented native `bind:group`; this pass changes its modern
  recommendation rather than claiming to repair the previously resolved mismatch.
- Single-value presence, bound reorder and callback rejection appear in the existing
  references and migration guide. Existing simple list/text snippets use the additions.
- `use*` helpers are component setup helpers. `.current`, MotionValue methods/direct
  styles, and `motionStore` are explained together; initial values and callbacks are
  deliberate getter-convention exceptions.
- `useAnimate.settled` documents results, reasons, pause/replay, repeated observers,
  sequences and external ownership without changing completion-only `finished`.
- `useFollowValue` defaults to spring, supports explicit tween/inertia, and retains
  borrowed-source ownership. `useWillChange` is explicit and makes no GPU promise.
- `animateView` documents the actual fluent methods, synchronous chain, selection,
  conditional versus unconditional snapshots, document ownership and fallback outcomes.
- `MotionConfig.isStatic` is excluded as an internal upstream flag; documented
  alternatives have distinct semantics. vgpu/Threlte remains outside core dependencies.
- Installation uses the supplied `astra-motion-0.1.0-rc.1.tgz`, requiring no checkout
  or library build. This is preparation guidance, not a claim of registry publication.

Complete recipes were added to existing pages, not new duplicate pages: native
checkbox grouping, changing panels, accordion, native dialog, headless Bits UI dialog,
following values and fluent View snapshots. Custom-root forwarding remains on the
Motion page and is expanded in the authoring guide.
